Overview

An automation tool built at Ammar Bin Ashfaq General Trading, where the team buys, repairs and resells fleet vehicles: taxis, delivery cars, vans, pickup trucks and fleet motorcycles. Staff used to check each auction site by hand for new listings. The tracker does the checking and texts them instead.

What It Does

Multi-Site Monitoring | Checks four to six vehicle auction sites in Fujairah and Sharjah, pulling listings through a mix of website monitoring and site data feeds, and picks out vehicles that match the defined models and price ranges.

Listing Alerts | When a matching vehicle is added, buyers get an SMS with its make, model year and starting bid.

Auction Type | Each alert says whether the auction is online only, in person only or both, so the buyer knows how to take part.

Bid Updates | Follows the auctions buyers care about and sends updates when a bid is placed, or when none has been.

How It Runs

Deployment | Python-based, running continuously on a company machine.

SMS Integration | Plugs into the company's existing bulk SMS software, which sends one message to many numbers under a single sender name, like a telecom notification. Buyers receive alerts through a channel the company already uses.

Business Impact | Replaced manual checking of every auction site, so buyers hear about suitable vehicles as soon as they are listed.

7

Overview

An AI-powered real-time recognition system built as a BSc final year project at Middlesex University Dubai. Initially designed for security applications in public transport settings, VisionAI combines object detection with facial emotion recognition in a single live video pipeline.

User testing with 20 participants showed real-world performance exceeding the validation metrics: 55% rated it "Very Good" and 75% said it exceeded their expectations.

How It Works

Object Detection | YOLOv8l (large model) runs on each video frame, detecting and labelling all objects with bounding boxes and confidence scores.

Emotion Recognition | When a person is detected, Haar Cascade classifiers isolate the face region. The face is normalized and passed into a custom CNN trained on FER2013, classifying one of 7 emotions: angry, disgusted, fearful, happy, neutral, sad, or surprised.

Deployment | A Flask web app streams the annotated live feed via multipart HTTP, with no page refresh required. The app auto-opens in the browser on launch.

Model Architecture

Custom CNN with 4 convolutional blocks (32 → 64 → 128 → 256 filters), batch normalization, max pooling, and dropout after each block. Trained for 50 epochs on 48×48 grayscale images with Adam optimizer and categorical cross-entropy loss. Approximately 2.36M trainable parameters.

Handwritten Digit Classifier
95.51%

550

Overview

A neural network built to classify handwritten digits using the UCI Optical Recognition of Handwritten Digits dataset. The focus was on selecting the right architecture, tuning hyperparameters, and validating generalization through two-fold cross-validation.

Approach

Algorithm Selection | Started with sigmoid activation, switched to a linear classifier which overfit badly, then returned to sigmoid with focused hyperparameter tuning to achieve stable results.

Architecture | Hidden layer with 64 neurons, sigmoid activation, L2 regularization (rate 0.00005), and learning rate decay from 0.01 down to 0.0095 over 550 training cycles.

Validation | Two-fold cross-validation: trained on Dataset1, tested on Dataset2 (95.05%), then swapped (95.98%), averaging 95.51%. Confusion matrices confirmed minimal misclassifications, mainly on digits 1, 4, and 9.

Python NumPy TensorFlow scikit-learn UCI Dataset

Overview

A car inventory and sales application built for the NCC Level 5 Computing Project at Aptech Doha. Staff log in, add cars with photos, and move them between Available and Sold lists as sales happen.

Features

Accounts | Sign-up and login pages with credential verification before access to the Available Cars page.

Inventory | Add a car with make, model, year, mileage, colour and price, plus a photo. Empty fields are rejected so incomplete listings are never saved.

Sold and Scrapped | A pop-up captures the final sale price and moves the car to the Sold Cars page. Scrapping a car deletes the listing.

Image Storage | Car photos are uploaded to Firebase cloud storage and displayed in the car list.

Under the Hood

Backend | Flask routes render each page and handle login, adding, selling and scrapping. SQLAlchemy with SQLite stores cars and users; a single Car table serves both lists, filtered by a sold status flag.

Frontend | Jinja templates built from a shared base layout, styled with CSS. JavaScript drives the pop-ups, logout confirmation and photo upload.

Packaging | Bundled into a standalone executable with PyInstaller and flaskwebgui, so it runs like a desktop application.
